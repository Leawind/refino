# @refino/cordis-plugin-refino 设计

对 dsh 的薄适配层：把 `@refino/harness` 的任务界定能力接进 dsh 会话。跨包契约（注入协议、签发机制、工具语义、v1 边界）见 [docs/design.md](../../docs/design.md) 的"harness 与工具插件功能设计"，本文只记录包内决策。

## 职责边界

本包提供：

- Cordis 插件入口：会话启动时从会话 cwd 向上定位 `.refino/`、打开工作区、注册全部工具、按会话来源注入初始上下文或授权状态行；会话销毁时释放工作区与降噪器
- 模型侧工具的宿主声明：参数/输出 schema 与工具名，执行与渲染转发到 harness 执行核心
- 审批面调用与消息注入

会话工作区、外部变更降噪、工具执行核心、签发链、注入文本与结果渲染均来自 `@refino/harness` 单一实现，本包不再持有这些模块。

本包不提供：图数据模型与查询（引擎）；`.refino/` 读写与定位（存储层）；授权计算、冻结区判定、上下文渲染与 delta 事件（harness）；任何持久化签发状态（对话签发只存在于会话内存，插件不产生文件）；授权控制台 UI（后继增强，见 docs/design.md）。

## 会话态

- 每 agent 一个工作区；工具经惰性解析，注册顺序无关，agent 销毁后调用得到结构化错误而非崩溃
- 初始化在宿主的 `agent/created` 串行阶段内完成：工作区打开、工具注册与初始上下文注入都先于首个模型请求；该阶段返回的 Promise 由宿主等待，不能改为后台异步，否则首轮会看不到工具与上下文
- 授权来源记录（默认 / 编排者 / 会话签发，含签发时间）由状态工具与注入行共同消费；编排者凭据在会话启动时解析一次，失败回落默认并告警
- resume 不重放基线（已在会话日志中），只注入一行当前授权状态——会话内签发随旧进程消亡，模型不得凭会话日志中的记忆行事
- 图超过自动锚点预算时不静默：注入极简引导（图已连接、节点数、根决策摘要、以搜索定位）

## 注入

- 注入是持久的 plugin-sourced 用户消息；对已销毁 agent 的注入静默丢弃
- 注入文本以 `<system-reminder>` 框架包裹；节点文本内的闭合标签会被转义，仓库内容不能提前闭合框架
- 文本中的工具指称与工具名单一来源，模型看到的名字与可调用的名字一致
- 更新通知为纯 ID 形态（详情经查询工具按需取）；渲染文本是变更集合的纯函数，"与上一次注入相同 ⟺ 零增量信息"，据此丢弃重复注入
- 外部变更链路：Store 监听 → 降噪合并（设最小注入间隔）→ 注入；模型自身的写入不经注入，其待审查集随工具结果返回

## 对话签发

- 宿主审批面缺失时不抛异常，fail-closed 返回不可用（失败面是签发未生效，不是工具报错）
- 批准即签署：会话内即时生效、以 delta 注入新冻结区；拒绝 / 取消 / 不可用一律维持现状；编排者凭据生效时直接拒绝——任务内授权不可自我扩张

## 工具面

- 查询工具全部批量、部分成功：未知 ID 以逐条错误返回，不阻断其余结果
- 写入工具在落盘前走同一条链（harness 核心）：引擎 grounds 校验 + 冻结区判定；越界返回结构化升级报告作为正常工具结果，非报错
- 宿主 schema DSL 表达不了的参数约束在执行核心里校验并以工具错误呈现

## 测试与依赖策略

- 单元层依赖经接口注入，用 testkit 的临时 `.refino/` 夹具；宿主层用真实裸 Cordis Context 驱动真实入口
- 与宿主的契约（事件时序、scope 派发、注入落真实会话日志、工具 schema 兼容）以一次真实 `dsh --profile headless` 会话复核：临时仓库放置 `.refino/`，以真实宿主加载本 bundle，确认首轮请求已携带插件工具与初始上下文；每次宿主版本前移时重做
- 涉及 `.refino/` 向上定位的测试必须从干净的临时目录出发——开发机家目录可能存在真实 `.refino/`，向上查找会命中用户数据
- `@deepseek-ai/*` 以精确版本锁定：dsh 处于 developer preview，宿主版本一变即安装失败（fail-fast），每次升级需人工核对后整体前移；对 dsh 的依赖面刻意收窄（上下文、工具定义助手、消息构造）
