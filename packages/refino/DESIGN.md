# refino 设计

## 职责边界

本包提供（纯引擎，零运行时依赖）：

- 常驻图数据模型：id、type、summary、grounds（父引用）、children（图内派生的子引用）、premise 的 confirmed、decision 的 exploring
- 图结构组装与内存变更原语：按 ID 索引、grounds↔children 双向引用回填与一致性维护
- 图结构完整性校验（引用解析、成环检测）与写入前 grounds 变更校验
- 按 ID 查询节点、遍历依据链与依赖链
- 最长路径分层：按 grounds 方向计算拓扑层级，环输入下按确定性规则近似
- 批量查询的标准结果形状与批量执行助手（部分成功语义），供各消费方统一使用
- ID 规则的定义与校验，及随机 ID 生成

本包不提供：

- 节点内容（正文、理由）的表示与分页供给：引擎类型不携带内容字段，内容按 id 由存储层按需提供
- 存储格式的定义、文件读写、解析、序列化（由存储层承担，引擎只消费其产出的常驻内存图）
- 任务上下文（作用域锚点）、冲突检测与复核提醒
- 可视化界面、命令行接口

## 内存模型

图可能达到 10⁶ 节点规模，引擎按"常驻 + 分页"划分内存：常驻集（渐进披露的第一级）始终在内存中，是引擎类型的全部内容；正文与理由等大字段不进引擎内存，由存储层按 id 分页供给。渐进披露（先读摘要判断相关性、再展开全文）只需要常驻集即可完成第一级。

生效探索状态与待审查状态都是派生态：前者沿依据闭包在读取时计算，后者通过查询前提的依赖关系确定；均由应用在内存中按需求值，不在节点文件中持久化。

## ID 规则

节点 ID 的生成与校验由本包统一定义，各包统一调用本包、不各自定义规则：字符集为大写字母、数字与下划线；长度 3–16 字符。随机 ID 自动生成的具体编码是内部实现细节，其产物天然满足上述规则。

## 校验问题（issues）

issues 是对图做完整性检查后产出的问题列表，归属字段由产生方定义：

- 引擎 issues 产生于两个阶段：结构校验（依据引用不存在的节点、决策→决策路径成环）与写入前变更校验（只报告该变更引入的问题，不报告图中既有问题）。引擎 issues 不含任何文件路径词汇。
- 存储层 issues 产生于加载解析阶段（frontmatter 非法、文件路径形状非法、重复 ID、时间戳格式非法等），每条额外携带规范文件路径。

issues 只描述图及其存储的问题，与任何消费方无关；如何处置（阻断操作或附带展示）由消费方自行决定。
