# @refino/storage 设计

本包是 `.refino/` 目录的唯一读者和写者。本文定义的存储格式同时约束 TypeScript 与 Rust（crate `refino-storage`）双实现；逐字节形状以代码与黄金用例测试为准。

## 职责边界

本包提供：

- 常驻投影 Store：常驻图（拓扑 + 摘要 + confirmed + reviewed）驻留内存，写入方法内部完成校验、原子写、增量应用与 issue 复检；API 写入与外部文件事件走同一增量入口；可选内建变更监听
- 加载 `.refino/` 目录并构建常驻内存图（图逻辑委托引擎；正文与理由不驻留）
- 内容分页：按 ID 按需读取节点内容，带 LRU 缓存；检索匹配语义（id 前缀、摘要、正文与理由）在此定义，供双实现共用
- 创建、更新、删除节点文件；原子写（临时文件 + rename），并发读取与监听不会撞上写了一半的文件
- 存储格式的定义：目录结构、节点文件格式、解析、序列化与摘要提取规则
- 问题报告：存储格式问题以本包定义的 issue 报告，每条携带规范文件路径（文件路径是持久化词汇，只出现在本包）；图级语义复用引擎的码

本包不提供：图数据模型与图逻辑（引擎）；ID 规则的定义与校验（引擎统一定义，本包只负责将合法 ID 映射为安全路径）；命令行接口与可视化界面。

## 存储布局

```
.refino/
└── nodes/
    └── <id_1>/
        └── <id_2>-<node_type>.md
```

- 节点全部放入单一顶层目录 `nodes/`，不区分类型子目录；`<node_type>` 取 `premise` 或 `decision`。
- `id_1` 为节点 ID 的前 2 个字符（分片目录名），`id_2` 为其余字符；`-` 是 `id_2` 与类型之间的专属分隔符（节点 ID 不含 `-`，无歧义）。
- 该形状天然规避 Windows 保留设备名（保留名均不含连字符，分片目录名固定 2 字符）。

## 路径即身份

节点 ID 与类型完全由文件路径推导：按文件名主段中唯一的 `-` 切分得到 `id_2` 与类型，ID 为分片目录名加 `id_2`，无需依赖大小写区分。存储层不定义 ID 合法性规则，只负责将合法 ID 映射为安全路径；文件名不合形状时报存储 issue。同一 ID 的全部候选位置恰为两条路径（两种类型各一），ID 全局唯一在写入时即可检出。

## 节点文件格式

每个节点文件是可选 YAML frontmatter 加 Markdown 正文；ID 与类型都不出现在文件内容中（类型由文件名表达）。

- 决策可用字段：`grounds`（依据 ID 列表）、`rationale`（理由）、`reviewed`（文件中为带显式 UTC 偏移的最后复核时间，内存中为 epoch 毫秒）、`exploring`（只在取 true 时落盘，缺席与显式 false 均解析为定案；生效探索状态不落盘，由引擎沿依据闭包读时派生）；创建时未指定 exploring 的根决策（依据为空）默认落盘 `exploring: true`——根决策先以试行入图，复核后转正；该默认只作用于创建，更新不会因 grounds 变空而改写探索标记；
- 前提可用字段：`confirmed`（文件中为带显式 UTC 偏移的确认时间，内存中转换为 epoch 毫秒，重写时规范化为 UTC 形式）；
- 两类节点均可用：`summary`（独立摘要属性）；
- 未知字段，以及已知字段出现在错误类型的节点上（如 premise 文件声明 `grounds`），一律静默忽略，不作错误处理。

## 摘要规则

frontmatter 声明 `summary` 时直接采用；未声明时回退为正文首段、折叠内部空白为单行，超长截断。截断仅发生在回退路径上，显式 `summary` 字段与正文本身不限制字数。

## YAML 序列化规范形

写入侧使用受限发射器：只输出存储层已知的字段集合，输出形状钉死；解析侧接受任意合法 YAML（用户手写 frontmatter 不受写入规范形约束）。规范形的存在是为了让同一存储格式的双实现产出逐字节一致的结果，其具体形状由写入器的黄金用例测试锚定，以代码与测试为准，本文不复述。
