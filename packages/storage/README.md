# @refino/storage

CRG 文件系统存储格式的权威定义与实现，也是 `.refino/` 目录的唯一读写入口。

## 职责边界

本包提供：

- 加载：读取 `.refino/` 目录并构建内存图（图逻辑委托给 `refino` 引擎）
- 创建：写入前提节点与约束节点文件（ID 生成委托给 `refino` 引擎）
- 存储格式的定义：目录结构、节点文件格式、Markdown/YAML 解析、序列化与摘要提取规则

本包不提供：

- 图数据模型与图逻辑：校验、查询等（由 `refino` 引擎提供）
- 命令行接口、可视化界面

## 存储布局

```
.refino/
├── premises/
│   └── <分片>/
│       └── <文件名>.md
└── constraints/
    └── <分片>/
        └── <文件名>.md
```

- 节点类型由顶层目录决定：`premises/` 下的文件是前提节点，`constraints/` 下的是约束节点。
- 分片目录名为节点 ID 的前 2 个字符，文件名（去 `.md` 后缀）为后 6 个字符，均为 Crockford base32 字符（数字与 A-Z，不含 I、L、O、U），合起来构成 8 字符的节点 ID。

## ID 推导规则（路径即身份）

节点 ID 完全由文件路径推导：`ID = 分片目录名 + 文件名`。因此不存在"ID 与分片不符"的情况；加载时校验的是路径形状本身——非法分片目录与非 Markdown 文件被静默忽略，分片内文件名不足 6 个合法字符报 `INVALID_ID`，直接出现在类型目录下的节点文件（旧布局残留）报 `INVALID_NODE_PATH`。

## 节点文件格式

每个节点文件是可选 YAML frontmatter 加 Markdown 正文：

- frontmatter 字段：约束节点可用 `grounds`（依据 ID 列表）与 `rationale`（理由）；前提节点可用 `confirmed`（RFC 3339 带显式 UTC 偏移的确认时间）。
- ID 不出现在文件内容中。
- frontmatter 中的未知字段一律忽略，不作错误处理。

## 摘要提取规则

节点的 `summary` 取正文首段，折叠内部空白为单行；超过 100 字符时截断并追加 `...`。
